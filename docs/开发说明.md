# 开发说明

给改代码的人看的：这份文件说明每块代码负责什么、自检命令怎么用、几个踩过的坑。
面向使用者的说明在 [`使用说明.md`](使用说明.md)。

## 工程

| 项 | 值 |
|---|---|
| 目标框架 | `net10.0-windows10.0.19041.0`（用 Windows SDK 版本的 TFM 是为了拿到 WinRT `MediaPlayer`：它能直接播 http(s) 与 FLAC，WPF 自带的 `MediaPlayer` 不能） |
| 唯一 NuGet 依赖 | `Jint` 4.18.1（执行落雪 / LX 脚本） |
| 程序集名 | `Darius Music`（工程名沿用 `CurrentLyrics`） |
| 入口 | `Program.cs`（`StartupObject=CurrentLyrics.Program`），先解析命令行自检参数，再进 `App` |

## 自检命令

全部在 `Program.cs`，都是「跑一遍、写报告/截图、退出」，不需要点鼠标：

```powershell
# 把桌面歌词渲染成 PNG（不需要音频）
& ".\Darius Music.exe" --shot out.png --pos 7600 [--lrc 文件] [--translation 0] [--scale 1.5]

# 主界面 / 设置 / 界面外观截图
& ".\Darius Music.exe" --ui-shot shots --folder D:\Music [--online 关键词] [--playindex 1]

# 无界面播放校验：扫描、播放、打印媒体时钟与当前歌词行
& ".\Darius Music.exe" --selftest --folder D:\Music --report selftest.txt

# 更新链：读清单 → 验签 → 下载 → 装版本 → 切指针（不重启）
& ".\Darius Music.exe" --install-version https://example.com/feed --install-log out.txt
```

用于回归的具体 QA（`--glow-color`、`--glow-picker`、`--slider-click`、`--end-advance`、`--glow-audit`、`--addtoplaylist` …）在每个参数旁边的注释里写了它验什么、看哪几个数字。

## 几个容易踩的点

- **数据目录跟着 exe 走**：`Layout.Root` 是 `versions` 的上一级；直接跑 `versions\vX\Darius Music.exe` 时数据仍落在根目录。测试一定要用 `DARIUS_DATA_DIR` 隔离，别动真数据。
- **`AppSettings.Normalized()` 是白名单**：新增字段必须同时加进 `Normalized()`，否则保存时会被丢掉。
- **WinRT `MediaPlayer` 换源有竞态**：上一路媒体还没拆卸完就赋新 `Source` 会被静默忽略（表现为进度条停在 0:00、没有声音）。`PlaybackService` 里因此有 1.4 s 看门狗，不要随手把 `Stop()` 写成「清空 Source」。
- **`PixelFormats.Pbgra32` 必须预乘**：霜化背景、辉光位图都自己算像素，RGB 必须已乘过 alpha，否则分层窗口上会出现一条硬边。
- **辉光是"光"**：颜色暗到接近黑就看不出效果，属正常行为，不是 bug。
- **XAML / csproj 也算源码**：PowerShell 的 `Get-Content | Set-Content` 会按 GBK 读 UTF-8，写回就乱码（工程文件直接编译失败）。请用编辑器或 `[System.IO.File]::ReadAllText / WriteAllText`。
- **合成鼠标进不了某些控件**：要求 `e.LeftButton == Pressed` 的处理器（如取色面板的拖动）收不到 `PostMessage` 的按键状态，写 QA 时绕开它。
